# M1 实测指南

本文档指导在**真实校园网环境**下验证 CampusNet-Keeper M1 的核心功能。
M1 提供命令行形态（设置界面在 M2），全程只需几步，请按顺序执行并保留每一步的输出。

> 程序位于 `build/Release/CampusNet-Keeper.exe`（下文简写为 `CampusNet-Keeper.exe`）。
> 建议在 **Windows 终端（cmd 或 PowerShell）**中运行，以便交互式输入密码。

---

## 0. 前置检查

    CampusNet-Keeper.exe --version

预期输出 `CampusNet-Keeper 0.1.0`。若提示找不到命令，请先 `cd` 到程序所在目录
或使用完整路径。

---

## 1. 确认当前网络状态

在校园网已连接并已手动登录的状态下运行：

    CampusNet-Keeper.exe --probe-now

预期输出：

    == 探测 ==
    探测地址: http://www.msftncsi.com/ncsi.txt
    结果: Online（网络正常）

- 若输出 `PortalDetected（被 Portal 劫持）`，说明探测地址被劫持（常见于认证失效）。
  **请把完整输出贴回**，我们需要据此调整探测地址。
- 若输出 `Offline（无连接）`，说明探测地址不可达（尚未连上 WiFi / 未获取到 IP）。
  恢复连线后重试；仍不行请贴回输出。

---

## 2. 识别厂商与运营商

    CampusNet-Keeper.exe --detect

程序会先抓取门户页面再识别（劫持态抓取跳转目标页；已登录态从配置的
`auth_url` 抓取——请先完成第 4 步，否则退回探测响应、可能显示 `unknown`）。

预期输出示例（**在门户注销、处于被劫持状态下运行**）：

    识别来源: http://10.0.0.1/a79.htm（已抓取门户页面）
    识别厂商: drcom
    Server: DrcomServer1.0
    运营商列表（服务器下发）:
      [1] 校园用户（无后缀）  <= 默认
      [2] 校园电信  后缀=@dx
      [3] 校园联通  后缀=@lt
      [4] 校园其他（无后缀）
    服务器未下发免劫持地址清单

关于最后一行：免劫持清单只在 `:801` 的 `loadConfig` 响应中下发，M1 暂不抓取该
接口，探测地址使用内置默认（`www.msftncsi.com/ncsi.txt`，该地址在真实清单内）。

**请保留完整输出**——其中的运营商列表与 Server 头是我们判断你学校 Portal 形态的直接证据。

---

## 3. 录入凭据（设置一次即可）

M1 没有设置界面，用 `--set-password` 录入一次密码（Windows DPAPI 加密存储，
配置文件被拷走也无法在其他机器解密）：

    CampusNet-Keeper.exe --set-password --user=你的账号

- `--user` 填**不含运营商后缀**的账号（例如 `2024147xxxxx`），
  服务器会按你在配置中选择的运营商自动拼接后缀。
- 运行后按提示输入密码（输入不回显，回车确认）。
- 若不方便交互输入，也可用环境变量方式：

        set CNK_PASSWORD=你的密码
        CampusNet-Keeper.exe --set-password --user=你的账号

  成功后输出 `密码已用 Windows DPAPI 加密保存。`

---

## 4. 完善配置

用记事本打开 `%APPDATA%\CampusNet-Keeper\config.json`，确认以下字段：

| 字段 | 填什么 |
|---|---|
| `profiles[0].auth_url` | 你学校的认证网址，本机目标为 `http://10.0.0.1/` |
| `profiles[0].isp.preset` | `cmcc`（移动）/ `telecom`（电信）/ `unicom`（联通）/ `campus`（校园网）/ `custom` |
| `profiles[0].username` | 已在第 3 步写好，不应含后缀 |

> 本机实测：在线会话的账号后缀为 **`@cmcc`**（移动），即 `isp.preset` 应设为 `cmcc`。
> 若第 5 步报"账号或密码错误"，可再试 `campus`（无后缀）。
>
> ⚠ `--detect` 打印的运营商列表来自**注销页**，实测其中**并没有** `@cmcc` 项，
> 而真实已登录会话用的确是 `@cmcc`——两者可以不一致。**以能真正登录成功的后缀为准**
> （本机已用浏览器 HAR 里的密文逐字节核对：账号串就是 `账号@cmcc`）。
>
> 密码字段（`password_enc`）是加密密文，**不要手改**。

---

## 5. 试登录（关键一步）

**注意：这一步需要你先主动断线**，否则服务器会认为你已在线。

断线方法：打开校园网门户页面，点「注销」。

注销后立即运行：

    CampusNet-Keeper.exe --test-login

预期输出示例（**2026-10-16 晚起：真实登录通道是 `:801` 的新式 API**，
`params` 为 AES 密文，因密钥公开于门户页面故一律打码为 `***`）：

    == 探测 ==
    状态: 被劫持
    说明: 被重定向到 http://10.0.0.1/a79.htm
    门户页面: http://10.0.0.1/a79.htm（已抓取，识别基于页面响应）
    识别厂商: drcom
    Server: DrcomServer1.0
    认证策略: DrcomAuth
    运营商后缀: @cmcc

    == 请求（已脱敏）==
    http://10.0.0.1:801/eportal/portal/login?callback=dr8003&params=***&jsVersion=4.X&v=***&lang=zh
    {"login_method":1,"user_account":",0,***","user_password":"***",...,"rcn":"***"}

    == 结果 ==
    成功: 是
    信息: 服务器返回登录成功（Portal协议认证成功）

    复测探测...
    复测结果: 已在线 OK

若**你并未注销**（终端仍在线，服务器拒绝重复登录），程序按成功处理并显示：

    成功: 是
    信息: 服务器报告该终端已在线（无需重新登录）：终端IP已在线！

> **重要**：`--test-login` 在**探测到已在线**时根本不会发登录请求，而是直接提示
> 「当前已在线，无需登录」并退出。所以真正的登录验证**必须在注销后**进行。

**请把完整输出贴回**。需要关注：

- `门户页面` 一栏是否显示「已抓取」（识别输入应为跳转目标页，302 本身不含指纹）
- `识别厂商` 是否为 `drcom`、`Server` 是否为 `DrcomServer1.0`
- `认证策略` 是否为 `DrcomAuth`
- `== 请求（已脱敏）==` 第一行是否指向 **`:801` 的 `/eportal/portal/login`**（新式 API，
  与门户**不同端口**；`params` 是 AES 密文，因密钥公开于门户页面故打码为 `***`）。
  若这一行是 `/eportal/?c=ACSetting`（老式回退通道），说明新式接口没被用上——
  该通道在本部署不做真实认证，会在 `信息` 里回 `userid error2`，
  **那是老通道的假象，不代表密码错误**
- `== 结果 ==` 一栏是否 `成功: 是`；成功时随后会显示 `复测结果: 已在线 OK`
- 若失败，`信息` 一栏的原文（这是最有价值的信息；新式通道会带服务器的 `msg`/`ret_code`，
  老式回退通道会带 `msga` 判定码——请一并贴回）

> 可选（补证据用）：在注销状态下先用 `curl.exe -s --noproxy "*" -D - -o NUL
> --max-time 8 http://www.msftncsi.com/ncsi.txt` 抓一次劫持 302 的原始响应头
> 并贴回（用于留存"302 无指纹"的直读证据）。

---

## 6. 后台守护测试

    CampusNet-Keeper.exe

托盘出现 CampusNet-Keeper 图标即启动成功（双击图标有气泡提示，右键有菜单）。

然后正常使用电脑。当会话失效（几小时到几天不等）时观察：

- 托盘气泡是否提示「网络已恢复」
- 日志 `%APPDATA%\CampusNet-Keeper\logs\keeper.log` 中是否出现
  `连接恢复：网络已回到在线状态`

---

## 需要反馈的内容

1. `--probe-now` 的完整输出
2. `--detect` 的完整输出
3. `--test-login` 的完整输出（**含失败信息**，这是最有价值的）
4. 守护运行一段时间后的日志尾部（`keeper.log` 最后 20 行）

**贴回前请自行确认输出里没有明文密码**——程序已对输出做脱敏
（密码与账号字段均显示为 `***`），但仍请扫一眼。
